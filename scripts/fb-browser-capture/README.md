# Local Marketplace capture producer

This deterministic Chrome MV3 producer feeds the existing `scripts/fb-import-urls.ts` and canonical `extract-facebook-marketplace` browser-capture owner. It reads rendered vehicle search cards and, when explicitly enabled, Marketplace item cards in Saved, using one dedicated, extension-created tab. It does not adopt other tabs, use page-world/hidden state, extract credentials/cookies, invoke inference, or contact another source. Search cards retain original displayed text, accessibility label, image URL/alt witnesses, displayed filters, region and capture clocks in immutable packets. Source listed time remains unknown; Sold/Pending are attributed displayed labels, not confirmed vehicle sales.

Initial installation is **disabled**. The popup provides Start/Resume, Pause, Run-if-due and status. Saved is **off by default**, including upgrades of an existing installation. Select **Include Marketplace items in Saved** to add exactly `https://www.facebook.com/saved/?cref=28`; this setting does not start a paused collector. The next eligible cycle visits Saved, then Saved and search alternate under the same 15-minute source cadence, at most96 total cycles per rolling24 hours, at most4 viewport scrolls and200 newly read cards per cycle. Each target is therefore due about every30 minutes while both are enabled. Target selection, due times and separate landing receipts survive worker/browser restarts. Turning Saved off preserves already staged packets and their replay.

Saved capture requires the observed `role=main` / `Preview of a saved item` container and a title plus Product price line within bounded ancestors holding one unique Marketplace item ID. It retains the original listing-title/asking excerpt and images attached to that same item link; it excludes other saved posts, seller account names, profile links and Saved controls. Missing or changed container shape, login/challenge, or navigation outside the exact expected target pauses visibly. The geographic market for Saved remains unknown and separate from search's displayed region. Saved membership supplies **unknown availability**, with `status_basis: saved_card_presence_not_availability`; it does not establish active status, a sale, or public visibility. Canonical intake keeps Saved capture/sighting evidence private and does not replace existing listing availability from membership alone.

Priority1960–1990 changes order only; encountered newer/unknown cards are retained. Each cycle splits into immutable packets of at most50 cards with a shared source-cycle ID. The unvisited tail is unknown on both targets. Repeated search/Saved visits are genuine new source attempts; repeating a pending packet is only landing replay. This revisits the bounded rendered collection, not every saved listing: deep/older items can remain unseen beyond four scrolls. Dedicated listing-detail revisits and full Saved enumeration are not implemented.

## Reviewed local installation

No browser policy or Codex extension/settings changes. Chrome's normal **Load unpacked** action is required; if the computer-use surface refuses privileged browser URLs, the owner performs that UI action. Do not work around that restriction.

1. From this pinned checkout, prepare the user-local native host:
   `node --import tsx scripts/fb-browser-capture/install-host.mjs`
2. In Chrome's Extensions management page, use normal Load unpacked and select this checkout's `scripts/fb-browser-capture/extension` directory. The public manifest key fixes ID `aidnmhdaljkomnocelhkcgogjonkjafi`; no private signing key is retained. The host accepts only that origin.
3. Open this extension's toolbar popup and click **Start / Resume**. It first checks the native host, then creates its own source tab. Pause remains available. Installation alone starts no source work.
4. To include Saved, explicitly check **Include Marketplace items in Saved** in the popup. Existing installations remain search-only until this action. The producer checks exact target scope before navigation/injection and again at every rendered scan; it never adopts the owner's already-open Saved tab.

The installer targets macOS user-local Chrome only. It checks pre-existing config/manifest ownership before replacing anything, leaves the immutable spool intact, fixes the executable PATH, and invokes installed Node/dotenvx with argument arrays. Existing credentials are read only by the existing CLI from the owner's established Nuke environment, never by browser code. Native commands are only ping and bounded capture packets; there is no shell command/path input, HTTP listener or tunnel.

Private packets/ACKs live in `~/nuke-logs/provenance-development-2026-10-11/fb-browser-continuity/captures`. The host preserves immutable packet bytes and CLI receipts, validates capture ID/clock and all raw/listing/sighting ACK counts, and caches a verified ACK. Exact replay reuses the same capture; changed testimony with an old ID is refused. Dead native-host locks recover without changing the packet. Browser local state retains up to8 pending packets; host refuses more than8 unacknowledged packets. ACKed originals are retained, not silently deleted.

Pending landing blocks new source work. Transient failure retries the same packet after1/2 minutes, at most3 attempts, then pauses for explicit Resume. Login/challenge/scope/load failures pause immediately with visible status. Queue and source limits are independent. Chrome worker sleep/reload preserves queue; browser startup clears the tab association and creates a fresh owned tab rather than adopting a user tab. Source-attempt interruptions and late scheduling are recorded, never counted as completed capture. The host/browser must remain available; alarms do not wake a sleeping machine. No continuous-availability, all-day operation or source-wide enumeration claim follows from this implementation.

If the owner navigates the collector tab elsewhere, collection pauses. Explicit **Start / Resume** after a scope error relinquishes that tab without navigating or closing it and creates a new owned tab only when the existing source schedule and budget allow; queued captures and their original bytes remain available for landing replay.
