# UI Audit — nuke.ag Frontend

**Date:** 2026-05-05
**Scope:** `nuke_frontend/` — React 18 + TypeScript + Vite + Tailwind
**Method:** 6 audit streams (3 Phase-1 Explore agents + 4 Stream agents). Static analysis only — browser walk denied; visual/rendered validation flagged as open gap.
**Supersedes:** `FRONTEND_QUALITY_REPORT.md` (2026-02-10), `THEME_AUDIT_REPORT.md` (2026-02-28), `QA_REPORT.md` (2026-02-10)

---

## Executive verdict

- **Substrate is shipped, UI is the bottleneck.** The hard architectural work (cockpit projection, External Agent Write API, journal/money projections) is done. What's left between *substrate live* and *strangers can land* is the rendering layer.
- **Tier 0 ship-blockers: 4.** Three structural (built pages not mounted; PROJECT_STATE lie) plus one mobile-killer (logged-out landing breaks at 375px).
- **Tier 1 polish: 11 categories.** Original 6 + 5 added 2026-05-06 from the gap-closure pass (mobile grids crush at 375px, 1.2 MB preload waste, missing image dimensions, /org route bloat, mobile-nav coverage gap).
- **After Tier 0 + Tier 1, "stranger lands and doesn't bounce" is plausible** — but unverified without a browser walk. See open gaps section.

### T0.2 — `/me/money` does not exist as a route
- **Stream B.** PROJECT_STATE.md (line 50) claims "Frontend page at `/me/money` (`ShopFinancials.tsx`) consumes [project_money_flow]." This is false. Grep for `/me/money` returns zero matches across `nuke_frontend/src/`.

### T0.3 — `PROJECT_STATE.md` reports surface as live when it isn't
- **Cross-stream finding.** The "Substrate-as-projection LIVE" block in PROJECT_STATE asserts journal + money are live public surfaces. Two of those claims are false. This is a project-state lie that future sessions and external agents will be misled by.
- **Fix recipe:** after T0.1 + T0.2 land, reaffirm. If the deciding answer is "park journal/money for now," remove the claims from PROJECT_STATE.

## Tier 1 — Polish before public launch

### T1.1 — Loading skeleton missing on the bounce-surface routes
- **Stream C.** Of 13 highest-priority public components inspected, **11 lack visible loading UI** during data fetch. Users see blank screens or `LOADING…` plain text. Pattern is inconsistent — three different ad-hoc text strings in three components.
- **Highest-impact misses (Stream C per-file table, abridged):**
  - `pages/AuctionMarketplace.tsx:66` — text only
  - `pages/UserProfile.tsx:22` — blank div
  - `pages/OrganizationProfile.tsx` — silent during fetch
  - `pages/journal/JournalPage.tsx:1` — inline `LOADING…`
  - `pages/journal/JournalIndex.tsx:39` — inline `LOADING…`
  - `routes/modules/marketplace/MarketDashboard.tsx:10` — pulse div, no message
  - `components/map/PublicMap.tsx` — no detail panel feedback
  - `pages/HomePage.tsx:1327` — text-only `LOADING...`
  - `pages/BrowseVehicles.tsx:609` — text-only
  - `pages/AuctionListing.tsx:62` — inline text
  - `pages/vehicle-profile/VehicleHeader.tsx:69` — only Suspense fallback
- **Fix recipe:** ship a shared `<LoadingSkeleton>` component (spec in appendix C) and replace each text fallback. ~30 min/file × 11 = one focused day.

### T1.2 — Silent error swallows on async paths
- **Stream C.** 24 silent catches across the app; the load-bearing ones for public flows:
  - `pages/HomePage.tsx:168-174` — `useTreemapBrands()` swallows RPC errors
  - `pages/BrowseVehicles.tsx` — `search.executeBrowse()` failure shows nothing
  - `pages/AuctionMarketplace.tsx:103-106` — silent
  - `pages/OrganizationProfile.tsx` — fails silently on profile fetch
  - `components/map/PublicMap.tsx:54-78` — silent on org/asset fetch
- **`react-hot-toast` is already a dependency.** Wire it via a `useToastError()` hook (spec in appendix C). Replace `.catch(() => {})` and `.catch(() => ({}))` patterns with `useToastError()`.

### T1.3 — Empty states missing on lists
- **Stream C.** Lists vanish silently on zero-result responses. `MarketDashboard.tsx:87` and `BrowseVehicles.tsx:762` are the worst offenders — `.map()` over potentially-empty arrays with no `if (!array.length)` branch. **Frontend rule (`.claude/rules/frontend.md`)** explicitly forbids "rendering CollapsibleWidgets whose body says No data available" and requires data-presence checks before render.
- **Fix recipe:** ship `<EmptyState>` (spec in appendix C); wrap `.map()` calls with length guards. Lint rule extension to `eslint-plugin-design-system.js` would prevent regressions.

### T1.4 — Critical public inputs are unlabeled
- **Stream E.** Two inputs on bounce-surface routes lack screen-reader labels:
  - `components/layout/SearchBar.tsx:98-112` — search input, placeholder-only
  - `pages/AuctionListing.tsx:172` — bid amount, placeholder-only (`type="number"`)
- **Fix recipe:** add `aria-label="Search vehicles"` and `aria-label="Bid amount in USD"`. 2-line fixes.

### T1.5 — Modal focus traps and missing escape handlers
- **Stream E.** Three modal patterns leak keyboard focus or have no Escape handler:
  - `pages/LocalVehicle.tsx:351-357` — lightbox, no Escape, no focus return
  - `components/vehicle/ScoreDetailModal.tsx` — no focus return after close
  - Modal patterns in `pages/settings/WebhooksPage.tsx` (3×) and `pages/add-vehicle/AddVehicle.tsx` (2×) — most use `<div className="fixed inset-0 ...">` without `role="dialog"` or `aria-modal="true"`
- **Fix recipe:** ship `<Modal>` primitive (spec in appendix D) with built-in focus trap, escape handler, and ARIA. 5 call-site migrations.

### T0.4 — Logged-out landing page (HomePage treemap) breaks at 375px (added 2026-05-06)
- **Appendix A.1.** The `/` route, when a stranger visits it logged-out, renders the treemap homepage. The treemap container has zero responsive breakpoints and a custom layout that crushes at 375px width. Header bar is unresponsive; treemap canvas squashes; no mobile-friendly fallback.
- **Why this is Tier 0:** this is the literal first thing a stranger sees on mobile. Bounce certainty is high if not fixed before public launch.
- **Fix recipe:** either (a) add a responsive treemap variant or (b) hide the treemap on `<768px` and route mobile users to the feed view by default. Option (b) is a 5-line change.

### T1.7 — Two primary discovery routes use grids that crush at 375px (added 2026-05-06)
- **Appendix A.1.** `BrowseVehicles.tsx:426` and `AuctionMarketplace.tsx:529,578` use `grid-cols: repeat(auto-fill, minmax(220px, 1fr))` and `minmax(280px, 1fr)` respectively. At 375px viewport, even one column overflows.
- **Fix recipe:** add `md:grid-cols-1` (or media query equivalent) to both grids. Two CSS tweaks.

### T1.8 — `maps-CxeXZlqt.js` (1.2 MB) is preloaded on every page (added 2026-05-06)
- **Appendix A.2.** `dist/index.html:48` ships a `<link rel="preload">` for the maps chunk. Maps are only used on `/map`; the preload wastes 1.2 MB of bandwidth on every other route. Vercel's compression makes it 333 KB gzipped — still a substantial waste.
- **Fix recipe:** remove the preload directive in `vite.config.ts` (or wherever Vite emits it). 2-minute change. Test with `npm run build` then inspect `dist/index.html`.

### T1.9 — Vehicle and org hero images lack intrinsic dimensions → CLS (added 2026-05-06)
- **Appendix A.2.** `pages/vehicle-profile/VehicleHeroImage.tsx:38` and `components/map/panels/MapOrgDetail.tsx` render hero `<img>` without `width`/`height` attributes. Browser cannot reserve space; layout shifts when image loads. CLS spike on the highest-traffic public route.
- **Fix recipe:** wrap in aspect-ratio container (`aspect-ratio: 4/3` for vehicle hero, fixed pixels for org logo). Three files, ~15 minutes.

### T1.10 — `/org/:slug` lazy-load is 618 KB (added 2026-05-06)
- **Appendix A.2.** OrganizationProfile.tsx (171 KB) and OrganizationOfferingTab.tsx (172 KB) load synchronously on the route, plus eager chunks. Total path-to-interactive ≈ 618 KB — the worst public-route offender.
- **Fix recipe:** lazy-import `OrganizationOfferingTab` inside its tab; only load when the tab is clicked. Cuts route-to-interactive to ~380 KB.

### T1.11 — Mobile bottom nav covers 3 of 13 public routes (added 2026-05-06)
- **Appendix A.1.** `MobileBottomNav.tsx` is wired into `AppLayout.tsx:172` and shows below 768px (good). But it links to 5 routes: Home, Search, Capture (auth), Inbox (auth), Profile. Only 3 of those are public-facing. Marketplace, journal, vehicle profiles are unreachable on mobile via the chrome.
- **Fix recipe:** decision required. Either (a) add `/market/trends` and `/journal` to the nav, or (b) accept that mobile discovery is hamburger-less and the AppHeader nav links carry the load (currently they're hidden below 768px — that needs to change too).

### T1.6 — Vehicle profile gallery and tab bar are not keyboard-navigable
- **Stream E.** Two of the highest-traffic public components are unreachable via keyboard:
  - `components/layout/VehicleTabBar.tsx:71-107` — tab elements are `<div onClick=...>`. No tab-role, no arrow-key handler.
  - `pages/vehicle-profile/VehicleHeader.tsx:4773` + `StorefrontVehicleDetail.tsx:166` — gallery thumbnails are `<div onClick=...>`. No focus, no arrow keys.
- **Fix recipe:** convert to `<button role="tab">` + arrow-key handler in parent. Concrete rewrite in Stream E section of appendix.

- **Stream D.** Phase 1 said 92 components import legacy `design-system.css`. **Stream D corrected this**: only **1 file** (`components/image/ImageLightbox.tsx:1`) still imports legacy. ### T2.4 — Tailwind dark-mode compat layer covers 43.7% of utilities

## How to use this audit

1. **Decide tier scope.** "Tier 0 only" = unblock public launch claim parity. "Tier 0 + 1" = visitor experience rises from 5/10 to ~8/10. "All tiers" = comprehensive, multi-week.
2. **Each finding has a file:line.** Spot-check three before committing — the entries point to the exact line a fix would change.
3. **Don't refactor monoliths atomically.** T2.2 (component splits) should be strangler-fig — extract the next time you touch each file.
4. **Add new ESLint rules to prevent regression.** `eslint-plugin-design-system.js` already exists; extend it for: no `<div|span> onClick>`, require empty-state branch on `.map()`, no raw hex outside `var(--token, #fallback)` fallbacks.
5. **File CRITICAL/HIGH items into `.claude/ISSUES.md`.** This audit doesn't auto-populate; QA loop expects it.

### `useToastError()` + ErrorBoundary spec

```tsx
// nuke_frontend/src/hooks/useToastError.ts
import { toast } from 'react-hot-toast';

export function useToastError() {
  return <T,>(promise: Promise<T>, opts?: { title?: string }) =>
    promise.catch((err) => {
      toast.error(`${opts?.title ?? 'Error'}: ${err.message ?? 'Unknown'}`, {
        position: 'bottom-right',
        duration: 5000,
        style: {
          background: 'var(--surface)',
          border: '2px solid var(--error)',
          color: 'var(--text)',
          borderRadius: 0,            // per frontend.md (no radius)
        },
      });
      throw err;
    });
}

// ErrorBoundary wraps AppLayout in App.tsx; toasts on render error.
```

### `useChartColors()` spec

9 files import recharts: `BidCompareOverlay.tsx`, `PriceHistoryChart.tsx`, `VehicleBidCard.tsx`, `ContractTransparency.tsx`, `IngestionTimeline.tsx`, `HeartbeatModelBar.tsx`, `UserMetrics.tsx`, `InventoryAnalytics.tsx`, `QuestionIntelligence.tsx`.

```ts
// nuke_frontend/src/hooks/useChartColors.ts
import { useEffect, useState } from 'react';

export function useChartColors() {
  const [colors, setColors] = useState({
    fg: '#2a2a2a', muted: '#999999',
    success: '#16825d', danger: '#d13438',
    info: '#0ea5e9', warning: '#b05a00',
    border: '#bdbdbd', surface: '#ebebeb',
  });

  useEffect(() => {
    const update = () => {
      const s = getComputedStyle(document.documentElement);
      const get = (k: string, fallback: string) =>
        rgbToHex(s.getPropertyValue(k).trim()) || s.getPropertyValue(k).trim() || fallback;
      setColors({
        fg:      get('--text', '#2a2a2a'),
        muted:   get('--text-muted', '#999999'),
        success: get('--success', '#16825d'),
        danger:  get('--error', '#d13438'),
        info:    get('--info', '#0ea5e9'),
        warning: get('--warning', '#b05a00'),
        border:  get('--border', '#bdbdbd'),
        surface: get('--surface', '#ebebeb'),
      });
    };
    update();
    const obs = new MutationObserver(update);
    obs.observe(document.documentElement, { attributes: true, attributeFilter: ['data-theme'] });
    return () => obs.disconnect();
  }, []);
  return colors;
}

function rgbToHex(rgb: string): string | null {
  if (!rgb.startsWith('rgb')) return null;
  const m = rgb.match(/\d+/g);
  if (!m || m.length < 3) return null;
  return '#' + m.slice(0,3).map(x => Number(x).toString(16).padStart(2,'0')).join('').toUpperCase();
}
```
