# Benchmark: "Is this a buy?" — CL 1979 Porsche 928, 2026-07-26

A real deal question, answered end-to-end in one session, used as a benchmark of the
deal system. Input was one message: a Craigslist URL + "is this a buy? flip [BaT search]".
Everything below actually ran; row IDs and counts are receipts, not estimates.

**The verdict the loop produced:** ask $11,500; first (condition-blind) read said strong
buy at band [17.5k, 35k]; image inspection downgraded to **pass-at-ask / offer ~$8k**,
band [12k, 18k] (prediction `hammer_predictions/8c7ec3ce`, vehicle `bcb4065d`). Seller
texted for VIN/belt/cluster; awaiting reply.

**The benchmark statement:** as a *data substrate* the system scored ~C+ — every organ the
loop needed exists, most were stale or partially covered, all were operable. As a *product*
it scored zero: no surface exists where this question can be asked or its answer rendered.
The entire loop ran through an agent with shell access. That is the gap.

---

## The loop, stage by stage

### 1. Deal discovery — FAIL (the listing never entered the system)
The 441-feed CL artery covers all ~416 metros for 1960–99 owner cars. This listing was
4 days old, in-scope, and absent from `vehicles`. Skylar found the deal by hand; the
sniper never saw it. Root cause unknown (poll interval vs regex vs ingest failure) —
and *diagnosing* it is itself hard because feed-landed stubs are geo-less/unpriced
(the known enrichment-crons-OFF debt from the Explore grounding).
**This is the single worst failure**: every downstream capability is worthless if the
deal never arrives.

### 2. Comps retrieval — PARTIAL (store excellent, coverage uneven, no demand-paging)
- `bat_listings` answered instantly with 2026 solds — but held only **28** 928 rows
  (2026-only) despite 100,848 sold rows spanning 2014–2026 overall. Coverage is
  model-lumpy and nothing surfaces that lumpiness; a naive query would have priced
  early 928s off n=3 and looked authoritative doing it.
- `external_listings` (the stale fork) quietly held the deeper truth — early cars at
  $102k–142k — which reversed the first "what makes a $100k car" answer. The canonical-seam
  debt (two stores, one truth) is a live correctness hazard, not hygiene.
- Fix demonstrated in-session: BaT's model-page API (`listings-filter`, `base_filter`
  wrapper) yielded the complete model history in ~50 requests. **971 unique 928 auctions
  backfilled** (828 new `bat_listings` rows + 187 new vehicles; 776 vehicles already
  existed from wave 1 — the organs really do exist). 928 coverage is now 875 listings /
  651 solds / 2015→today.
- Product shape this implies: **comps faulting** — when a cohort's coverage is thin,
  the system should pull the whole model-page history on demand (take the whole
  resource), not answer from the shard it has.

### 3. Condition read — the engine exists, nothing runs it (repeated the known failure)
First pass priced the car from the seller's words + comp titles = the exact
condition-blind failure the ledger already quantified (33–48% median error; prediction #1
missed by +83.6%). Only when challenged did the loop pull the 11 listing photos and look.
The images **flipped the verdict**: non-factory magenta respray with panel-to-panel sheen
mismatch; half-done interior color change (front black, rear still original red); 52k
odometer reading on a 170-mph (later-spec) cluster face → mileage unverifiable; unrestored
bay with hanging connector; straight rust-free AZ body underneath.
The appraisal organs to do this automatically exist and are dormant (three lineages,
`APPRAISAL_ENGINE_STATE.md`); nothing wires *listing photos* → condition features →
band adjustment. **The system's stated core differentiator is the part that runs zero
percent automatically.**

### 4. Verdict + ledger — WORKS (dormant but operable, and it earned its keep)
`hammer_predictions` accepted prediction #3 with comps, band, flip margin, and
recommendation; the image pass updated the same row with evidence-cited notes. The
two-pass record (blind → image-informed) is itself valuable calibration data: the
band moved from [17.5k, 35k] to [12k, 18k] on pixels alone. Verdict asymmetry held:
the buy call was only defensible while ask < project-grade hammer; once condition
evidence arrived, the entry price stopped clearing the bar and the verdict flipped.

### 5. Outreach — demonstrated, unowned by the product
Seller contact (name + phone) sat in the listing; a four-question text (VIN, original
color, timing belt, cluster originality) went out via iMessage in one step. The questions
were *generated by the verification gaps* the image pass opened — that is the product
shape: unresolved condition features → seller questions → answers close the loop and
re-score the band. Today this exists nowhere in the codebase.

### 6. Render surface — ABSENT
The answer lived in chat. No app/site surface can accept "URL + is this a buy?" or render
verdict/band/evidence/comp-curve. (Known: Explore is mislabeled, reads the sold census,
ignores the ask artery — the 2026-07-13 grounding stands.)

## What "good" looked like (keep these behaviors)
1. Answering from the substrate first — the H1 lesson held; rung 2 was queried before the web.
2. Take-the-whole-resource backfill — 971 listings, one house style, dupes ignored cleanly.
3. Ledger honesty — prediction logged *before* outcome, revised *with cited evidence*, wrong
   first pass left visible in the row instead of overwritten.
4. Images as verdict-movers, not decoration — a 2x-margin "buy" became "pass" on 11 photos.

## Shortest path from C+ substrate to a product loop (develop-from-what-exists)
1. **Discovery integrity first** (the F): diagnose why this listing missed; turn on the
   enrichment crons (geocode/price/dedup/expire) so misses are even diagnosable. Without
   this there is no product.
2. **Comps faulting**: a fetch-model-history function (the `listings-filter` recipe is now
   proven) triggered when cohort coverage is thin; writes through the same door the
   backfill used.
3. **Condition pass on listing photos**: revive the yono spectrometer path far enough to
   run on ask-side listing images and emit band adjustments — not the full part-entity
   fractal, just the verdict-mover demonstrated here.
4. **Verdict card surface**: one page/route: paste URL → comps curve (the 156-sold early-car
   percentiles), band, evidence thumbnails, recommendation, and the generated seller
   questions. This is the Explore relabel + the ask ladder meeting in one place.

Night-queue already holds: 928 comment backfill (bidder-flagged condition features for
early cars — feeds stage 3).
