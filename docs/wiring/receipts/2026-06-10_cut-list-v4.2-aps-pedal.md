## 2. THE DEVICE

**GM 10379038 Accelerator Pedal** — cited:
- `reference_documents/component_drawings/LS3_EROD_Engine_Controller_Kit.pdf` p.2 ("10379038
  Accelerator Pedal" in the kit content list; EROD guide p.1: "Don't: Change or alter any
  wiring in the accelerator pedal or electronic throttle systems")
- Atom: `K5_dimensions_atoms.yaml:294` (`ls3_erod.accelerator_pedal_pn = 10379038`,
  source LS3-EROD-Guide p.2)
- `reference_documents/component_drawings/Canems_LS3_LS7_harness_diagram.pdf` pp.3-4: the
  LS3/LS7 pedal occupies **six** loom positions (pedal pins A through F) — independent
  corroboration of the 6-wire count.

**Track architecture (verified, web):** GM APP sensors are **two independent tracks, each
with its own 5V reference and its own ground** — APP1 and APP2 do not share a supply or a
return. Sources: easyautodiagnostics.com GM APP sensor test guide (4.8/5.3/6.0L),
autosphere.ca "Accelerator Pedal Position Sensors" (2018-02-27). The redundancy is the
safety architecture: a single reference/ground fault must not be able to fake a throttle
command, and the ECU cross-checks the two tracks (APP correlation). Matches `devices.json`
`analog_5v_dual_track`. → 2 tracks × (signal + 5V + 0V) = **6 wires**.

**OPEN (not invented):** the per-cavity pin map of `gm_aps_6pin` (which letter = which
track/function on PN 10379038) is NOT in the library and was not found with confidence
online. Canems lists pins A–F but does not label their functions. This is a connector-level
detail — **connectors are deferred until after formboard (locked 2026-05-11)**, so it blocks
nothing now. Close it from the pedal pigtail/GM service data when connectors get spec'd.

## 4. PIN ASSIGNMENT DERIVATION (every choice cited)

### 4.1 Signals → AV7 (B21) + AV8 (B22)

M130 has exactly 8 analogue voltage inputs (techspec p.6 model comparison: "Analogue
Voltage: 8"). Occupancy after the v4 AV shuffle (`receipts/2026-06-09_cut-list-v4.md`) and
v4.1:

| AV | Pin | Occupant |
|---|---|---|
| AV1 | A14 | #4c ETB TPS1 (v4: newer decision wins) |
| AV2 | A15 | #108 MAP |
| AV3 | A16 | #112 Fuel Pressure |
| AV4 | A17 | #4d ETB TPS2 |
| AV5 | A25 | #102 Oil Pressure (moved from A14 in v4) |
| AV6 | B20 | **left free — standing candidate for #98 fuel level** (v4 receipt open item; v4.1 receipt §7.3) |
| AV7 | B21 | **→ #APS_T1_SIG (this receipt)** |
| AV8 | B22 | **→ #APS_T2_SIG (this receipt)** |

Pin identities from `motec_m1_hardware_techspec.pdf` p.17 (M130 Connector B table: B20 AV6,
B21 AV7, B22 AV8). AV7/AV8 were the only free AV pins that don't collide with the #98
candidate — zero-conflict assignment, no shuffle needed. Both signals land on Connector B
(Superseal 26), same connector as the SEN_0V pins.

### 4.2 Supplies → A02 (track 1) + A09 (track 2), letter-paired grounds B15/B16

- Pin identities: techspec p.16 (A02 SEN_5V0_A, A09 SEN_5V0_B), p.17 (B15 SEN_0V_A,
  B16 SEN_0V_B). M130 has exactly 2× +5V outputs (techspec p.6: "+5V Output: 2").
- **Letter-pairing rule:** the techspec's own pinout pairs supplies and returns by letter —
  the AT inputs alternate "1k Pull up to SEN_5V_A" (AT1/B03, AT3/B05) and "SEN_5V_B"
  (AT2/B04, AT4/B06) (p.17), and the 2026-05-14 companion addendum followed it (#109g→B15
  paired with AT1/SEN_5V_A; #110g→B16 paired with AT2/SEN_5V_B). APS follows: Track 1 =
  A-pair (A02 + B15), Track 2 = B-pair (A09 + B16).
- **Why the tracks split across the two rails:** the dual-track architecture only delivers
  its redundancy if the tracks have independent supplies and returns (§2 sources — GM gives
  each APP track its own 5V and ground). One rail fault → one track lost → M1 sees APP
  correlation error and fails safe, instead of both tracks drifting together.
- **Load check:** pot tracks are mA-class (device nameplate 0.05 A total, `devices.json`).
  A02 already feeds ETB (#4e), OPS (#102r), FPS (#112r), CKP (#99r); A09 feeds MAP (#108r),
  CMP (#101r). Adding one pot track per rail is negligible.
- **Pre-existing inconsistency surfaced, NOT fixed here:** the 2026-05-14 AV-sensor
  companions are letter-crossed (#102g→B16 + #102r→A02; #108g→B15 + #108r→A09; #112g→B16 +
  #112r→A02 — supply letter ≠ ground letter). Electrically functional (all SEN_0V pins are
  ECU ground reference) but it breaks the letter convention. Flagged as substrate
  inconsistency for a separate receipt if Skylar wants it normalized; per the closure
  protocol, not silently corrected inside this amendment.

### 4.3 Gauge, spec, colors

- **22 AWG:** signal floor per 2026-05-14 gauge-audit doctrine ("22 AWG floor for signals");
  matches `devices.json` gauge 22 and every other AV sensor wire in the registry.
- **M22759/32:** locked spec rule, 12–22 AWG = M22759/32 (2026-05-11 Tefzel amendment).
- **Colors per the established function map:** signals VIO-family (matches #102 VIO,
  #108 VIO/WHT, #112 VIO/BLK analog-sensor family) — VIO/YEL and VIO/ORG chosen because they
  collide with nothing in v4.2 (grep-verified). 5V refs GRY (matches #4e, #99r, #101r,
  #102r, #108r, #112r). Grounds BLK with BLK/WHT for the second of the pair (v4.1
  #ECU_GND1/#ECU_GND2 precedent). Reassignment at mockup allowed per locked decision
  2026-05-11 (heat-shrink labels carry circuit ID).

### 4.4 Length — 3.5 ft dash-zone estimate

Pedal hangs at the firewall under-dash (driver side, next to the brake pedal — EROD kit p.2
mounting-clearance drawing). 3.5 ft is the established dash-zone class (#40 ignition switch,
#53 brake light switch). Path entries use **L19** (PDM30 → brake pedal switch, 34.7" in
`K5_landmarks_blender_derived.yaml`) as the nearest same-zone proxy; computed value
4.09 ft/wire (`K5_computed_lengths.csv`, run this session: 142 wires, 0 blocked, 1160.5 ft).
The 0.6 ft delta between zone class and L19 proxy is inside the estimate noise — prototype
at the computed max length per Dave's method, then verify on vehicle. **No M130→pedal
landmark exists**; flagged `needs_rederivation` pending the M130 mount decision (§4 of the
state file — still OPEN) and pedal mount survey.
