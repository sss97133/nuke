# Route-point kind revisions

The current service-only `load_harness_topology_points` compares coordinates when deciding whether to retain a point. An explicit source correction from bulkhead/device to grommet at the same coordinates is silently discarded. The route graph then retains a classification its admitted source no longer states. Live definition hash before repair: d323b472b60d1a286600e65b779cc787.

Extend that same writer and append-only topology owner. Explicit kind changes create a new point revision and supersede the prior row; repeated identical geometry/kind remains idempotent. Missing or blank kind preserves the prior recorded kind, with the existing device default for a new point only. Text-only edits retain the row. Preserve old result counts and add points_reclassified as a subset of the historical points_moved revision count.

The disposable contract checks same-position correction, history, replay, omitted/blank kind with unchanged or moved geometry, the new-point default, refusal/rollback for an invalid existing enum value, service-only grants, and the existing branch loader relinking without a new branch or changed length. The original route-writer contracts remain unchanged.

This migration writes no source point, placement, wire, observation or material quantity. Current Blazer pass-through classification, endpoint/branch relinking, source admission, current evaluation route dependencies and electrical/physical fit still need their owned source-to-consumer work. A route-point kind never proves a wire is cut, joined or installed.
