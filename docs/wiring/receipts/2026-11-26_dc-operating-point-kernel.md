The next software acceptance is electrical behavior before fabrication. Existing `harness_model_nodes` and `(evaluation_id, segment_id, side)` attachments own evaluated terminal connectivity. Their existing contract is defined by the table and column comments in `supabase/migrations/20261125233922_harness_model_evaluation_loop.sql` lines47–70 and the corresponding `Harness structural evaluation and currentness` capability entry. They do not encode source voltage, load behavior or operating-state contacts. A terminal is not by itself an open/closed circuit. Conducting paths and device behavior determine the operating point.

This first change adds a pure, bounded compute helper, not another physical graph or source writer. Its explicit caller-supplied scenario is conditional simulation input, never automatically a qualified vehicle specification. The helper solves resistors, explicit open/closed finite-resistance contacts, independent voltage sources and independent current sources using modified nodal analysis. It returns keyed node voltage, signed branch current, absorbed power, current-conservation residual and power-conservation residual. Unknown contact state, missing parameters, unsupported behavior, floating networks and inconsistent ideal-source constraints do not produce usable results. No resistance, leakage path, ground bond, load, protection trip, route or manufacturer applicability is inferred.

Grounding: `docs/ledger/theory/data-machine-cases.md` §13.12 criteria7–8 require SQL conclusions bound to inputs and generated consumers; §13.12.1 distinguishes design predictions from observed outcomes. `chapters/16-wire-and-protection-canon.md` preserves voltage-drop and protection as engineering calculations with stated inputs. `K5_WIRING_STATE.md` §1–4 and `WIRING_SYSTEM_KNOWLEDGE.md` remain physical authority; this change assigns no physical value to a vehicle. The ngspice manual sections2.1.4,3.3.16 and4 document topology constraints and explicit source/switch models: https://ngspice.sourceforge.io/docs/ngspice-manual.pdf . Test quantities are labeled analytical fixtures, not truck ratings. The older referenced HARNESS_RULES.md and RECEIPT_FORMAT.md remain absent.

Capability check found no existing DC solver in CAPABILITY_MAP/TOOLS; extend the existing harness-model compute family. Existing conditioned wire-reference intake owns sourced resistance per length; do not copy its writer. Live atlas access timed out during preflight, so this slice creates no canonical source/result tables or competing registry. The helper has no table access, is SECURITY INVOKER, and is executable only by service_role. No existing evaluator logic snapshot, source epoch or public manual result is changed until a typed scenario/source-binding compiler is reviewed.

Plan: (1) prove bounded DC math and explicit failure modes in PostgreSQL; (2) bind operating scenarios, terminal pairs and parameter provenance to the existing typed harness owners and qualified references; (3) include that input/logic/result in the canonical immutable evaluation and invalidation path; (4) let schematic and worksheet consume the same keyed electrical state. Stage1 does not establish stages2–4 or full builder acceptance.

Acceptance: a labeled analytical source/wire/contact/load/return fixture conserves current and power; closing/opening the contact changes its solved current; increased wire resistance changes delivered voltage and loss; current sources and parallel loads conserve current; missing/unknown/floating/conflicting inputs fail explicitly; input ordering preserves keyed answers; malformed/oversized scenarios remain bounded. The regression contract uses no testimony tables or production writes.
