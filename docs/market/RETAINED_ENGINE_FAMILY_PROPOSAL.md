# Retained publisher engine-family labels

Proposal `6b9de10b-1666-4bdf-bb69-7e82d62f8b32` requests
`engine_family_label` through the existing schema curator. Its migration files an
**open proposal**. It does not ratify a property, write a review, admit an observation,
change a replay epoch or start a job.

The registered `engine_code` means **Casting / serial number-derived**. A literal
publisher M50-style family label has a different meaning and cannot be put there.
The proposed field preserves publisher testimony about the engine described as
powering the subject. Physical installation, factory originality, current
configuration, decoded identity and event time remain unverified.

The read-only prototype reuses the retained capture qualifier and existing
configuration/displacement witnesses. It requires a bounded powering sentence,
consistent configuration/displacement and one literal family token; it refuses
factory-only descriptions, stamp/photo references, component-style labels,
contradictions, other subjects and incomplete capture envelopes. It preserves the
quote, capture fingerprint and source/recording clocks. Existing intake modes and
property keys remain unchanged.

Thirty original qualified captures produced **one parsed, unadmitted M50 candidate**
and 29 refusals. The proposal cites its original observation and fingerprint plus
factory-only, non-powering and component counterexamples. This sample is discovery
evidence; it measures neither corpus coverage nor canonical admissions. The private
raw bodies and source-bound JSON remain in the operator evidence store.

The ingest suite passes 302 tests, including 22 prototype/refusal tests. The SQL
contract reuses the existing live-shaped curator fixture and real functions to
prove open status, no properties/reviews created, refusal to apply before approval,
unchanged curator grants/functions, repeat preservation and refusal to overwrite a
curator decision. Neither test creates production testimony.

Next checkpoints are deployment of the open proposal, a separately attributed
curator decision, then a separately tested existing-intake/reader implementation
if ratified. The workflow handbook requires a separate approver for an agent
proposal; this migration supplies no reviewer identity. Within seven days an open
proposal can be withdrawn and the unused prototype reverted while preserving the
original testimony. Bulk replay of already admitted properties continues throughout.
